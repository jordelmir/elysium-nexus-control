## §1. Principio fundamental

Pipeline: captura física → modelo canónico → procesamiento en tiempo real →
mapping semántico → transporte → backend de destino. La UI no conoce los
protocolos de PS / Xbox / Nintendo / macOS / Windows / Linux / Android.

## §2. Reglas de legitimidad y seguridad

Permitido: HID estándar, Bluetooth HID Device, HID over GATT, descriptores
propios, receptor físico propio, APIs oficiales, Remote Play, licenciamiento,
SDKs autorizados, código abierto conforme a su licencia, perfiles visuales

propios.

Prohibido: extraer claves criptográficas de controles oficiales, reutilizar
certificados de dispositivos comerciales, copiar secretos de hardware, usar
firmware filtrado, suplantar VID/PID de terceros, presentarse falsamente como
DualSense/DualShock/Xbox/Joy-Con/Pro Controller, evadir desafíos de

seguridad de una consola, distribuir código obtenido por violación de

## §3. Definición correcta de "universal"

Una sola APK, un solo modelo de entrada, un solo editor, un solo sistema de
perfiles, un solo protocolo Elysium Link, un solo emparejamiento, distintos
adaptadores de salida, distintos backends autorizados, compatibilidad
progresiva, mejor ruta disponible seleccionada automáticamente.

Prioridad de transporte: 1) Direct Standard HID, 2) Elysium Desktop Agent,
3) Official Remote Play, 4) Elysium Nexus Receiver, 5) Licensed Console
Backend, 6) Unsupported with explicit explanation. Nunca ocultar la ruta.

## §11. Superficie táctil Android

Compose puede controlar navegación, ajustes, editor, listas, pantallas no
críticas. El camino de entrada analógica debe evaluarse con una View
especializada (MotionEvent expone muestras históricas, permite seguimiento
por pointerId, reduce recomposiciones, facilita buffers reutilizables, da
control sobre cancelaciones). No actualizar un MutableState de Compose por
cada muestra del stick.

Pipeline: MotionEvent → Pointer extraction → Pointer ownership → Coordinate
normalization → Filtering → Control state update → Frame scheduler.

Manejar: ACTION_DOWN, ACTION_POINTER_DOWN, ACTION_MOVE, ACTION_POINTER_UP,
ACTION_UP, ACTION_CANCEL, cambio de orientación, multiventana, fold state,
pérdida de foco, screen off, Activity pause, app termination. Cada salida
abrupta → estado neutral.

## §12. Sticks profesionales

Modos: fixed center, floating center, hybrid center, relative trackpad,
flick stick, gyro-assisted stick, precision mode.

Configuraciones: radio, zona muerta radial, zona muerta axial,
anti-deadzone, saturación exterior, curva de respuesta, sensibilidad,
inversión, snap angular, recentrado, fricción visual, modo de rango
reducido, modo shooter, modo racing, modo flight.

Fórmula base:
```
m = sqrt(x² + y²)
if m <= innerDeadzone: output = 0
else:
    normalized = clamp((m - innerDeadzone) / (outerThreshold - innerDeadzone), 0, 1)
    curved = responseCurve(normalized)
    output = normalize(x, y) * curved
```

Property-based tests para: centro, bordes, negativos, simetría, monotonicidad,
continuidad, NaN, división entre cero, radios inválidos.

* Los valores nunca salen del rango canónico.

## §38. Prueba crítica de desconexión (release blocker)

1. Presionar 4 botones simultáneos.
2. Mantener ambos triggers.
3. Mantener ambos sticks fuera del centro.
4. Mantener D-pad diagonal.
5. Mantener touchpad activo.
6. Activar gyro.
7. Mantener una tecla.
8. Mantener mouse izquierdo.
9. Cortar Bluetooth y Wi-Fi abruptamente.
10. Apagar pantalla del Android.
11. Terminar el proceso del agente.
12. Reiniciar el receptor.
13. Verificar en el host: cero botones presionados; sticks centrados;
    triggers en cero; D-pad neutral; touch cancelado; teclas liberadas;
    mouse liberado; dispositivo anterior eliminado; ninguna sesión fantasma.
14. Reconectar.
15. Verificar que el primer estado sea neutral.

Resultado: 0 controles atascados, 0 dispositivos fantasma, 0 sesiones
reutilizadas, 0 eventos de una sesión anterior.

## §40. Soak test

≥ 12 horas: movimiento continuo, multitouch, gyro, haptics, cambios de
perfil, reconexiones, cambio de red, thermal throttling, screen rotation,
fold/unfold, background/foreground. Verificar: memoria estable, sin ANR,
sin crash, sin crecimiento de threads/handles, sin batería anormal, sin
sobrecalentamiento crítico, sin controles atascados, sin colas infinitas.
